# Запрет блочных комментариев `/* */`

В SQL, попадающем в репозиторий, не используем блочные комментарии `/* ... */` — только однострочные `--`. Потребность закомментировать несколько строк закрывается редакторами и IDE (построчное `--`), а `/* */` остаётся допустимым **локально**, для временного отключения кода при экспериментах; в коммит такие комментарии не попадают.

Отдельное решение понадобилось потому, что запрет не опирается на техническое ограничение. Тезис «первый `*/` закроет комментарий, следующий вызовет ошибку» для нашей основной СУБД неверен: PostgreSQL поддерживает **вложенные** блочные комментарии (см. `docs/research/sql-style-guides.md`, §2.7, ссылка на PostgreSQL §4.1.3). Также ядро SQLFluff блочные комментарии не проверяет, поэтому правило остаётся «проверяется линтером: нет». То есть запрет держится на единообразии и на границе «репозиторий vs локальный черновик», а не на невозможности или ошибке, и это стоит зафиксировать явно.
