# Раскладка DML: расширение «корневого ключевого слова» и канон списков

В стандарте `0.3.0` раскладка DML перестаёт быть непокрытой. Термин «Корневое ключевое слово» (`GLOSSARY.md`) расширен DML-клаузами, перенос которых проверяет линтер, — `values` и `set`; в оба профиля референсного конфига добавлены layout-секции `values_clause`/`set_clause_list` с `keyword_line_position = leading`, из-за чего однострочный `insert ... values (...)` становится невалидным. Клаузула `returning` в термин **не** входит: у неё нет узла-клаузулы в парсере SQLFluff, поэтому `LT14` её перенос проверить не может, и расположение `returning` регламентирует текст нового правила `FMT-016` (§5) — иначе `FMT-004` заявлял бы «проверяется линтером: да» для непроверяемого случая.

Правило `FMT-016` (§5) фиксирует канон форм DML-списков, оставляя допустимыми все три формы: (a) брекетный вид — `(` на отдельной строке, элементы с отступом в один уровень, закрывающая `)` по левому краю; (b) список из одного элемента — на строке с ключевым словом; (c) многострочный список без брекетов, элементы по левому краю. Канон (`SHOULD`) — форма (a) для нескольких элементов и форма (b) для одного; форма (c) допустима, потому что ровно её строит `sqlfluff fix`, и запрещать её — воевать с инструментом.

Допустимость трёх форм — осознанное отступление от мета-принципа §2 «единообразие важнее выбора». Основание: форма без брекетов навязана авто-фиксом, а форма с брекетами — ручным каноном, поэтому «один зафиксированный ответ» здесь недостижим без конфликта с `sqlfluff fix`. Цена отступления — критерий ревью даёт канон `FMT-016`, а не линтер: у форм списков конфиг-рычага нет (layout-секции на позицию скобки инертны).

Класс изменения — `MAJOR` по §9.1: ранее валидный однострочный `insert ... values (...)` перестаёт соответствовать стандарту. Так как документ ещё черновик (`0.x`), изменение выходит как `0.3.0`, и запись о нём добавлена в §9.3. Границы батча: `MERGE` целиком, раскладка `DELETE ... USING` и DDL-миграции (`create`/`alter`/`drop`) в это изменение не входят — регулируется только то, где линтер проверяет перенос (`values`/`set`) либо канон задаётся текстом (`returning`, формы списков).

Status: accepted
