# Спека: доработка стандарта кодирования SQL до v0.2.0

Status: ready-for-agent

> Реализацию начинаем после подтверждения владельцем: спека и тикеты показаны до правок `STANDARD.md`, конфигов и `examples/`.

## Problem Statement

Стандарт `0.1.0` закрыл Форматирование, Нейминг и ядро Синтаксиса, но по итогам использования всплыли пробелы и спорные места в аспекте Форматирование:

- термин «корневое ключевое слово» используется в правилах, но не определён, а его границы (что считать корневым) не зафиксированы;
- не сказано, допустимы ли короткие «идиоматические» запросы и где место `distinct`;
- расположение `on` и блочных комментариев `/* */` никак не регламентировано, при этом линтер допускает два стиля `on` одновременно;
- стиль CTE (расположение имени и скобок) не зафиксирован, а примеры опираются на `as (` без обоснования выбора.

Цель доработки — убрать эти развилки, не ломая уже принятые правила и сохраняя единообразие.

## Solution

Точечные правки существующих правил (`FMT-004`, `FMT-008`, `FMT-009`, `FMT-012`), два новых `SHOULD`-правила (`FMT-014`, `FMT-015`), удаление неработоспособного `FMT-011`, новый ADR-0006 и термин в глоссарии. Версия — `0.2.0`.

## Решения (грилинг владельца, 2026-10-31)

| # | Решение |
|---|---|
| 1 | `FMT-004` остаётся `MUST`; однострочные запросы не допускаются, короткий многострочный — норма |
| 2 | Запрет `/* */`: `MUST`, «проверяется линтером: нет», локальное временное использование допустимо; ADR-0006 |
| 3 | Комментарий — на отдельной строке над кодом: `SHOULD`, линтером не проверяется |
| 4 | Канон `from`/`join`/`on`: `from` и `join` по левому краю, `on` — на своей строке с отступом 4 (`SHOULD`) |
| 5 | Канон CTE: `with` на своей строке, имя по левому краю, `as` в конце строки имени, `(` на отдельной строке, тело +4, `)` по левому краю; без пустой строки между CTE и перед основной выборкой (`SHOULD`) |
| 6 | `distinct` остаётся на строке с `select` |
| 7 | Термин «корневое ключевое слово» (root keyword) — в `GLOSSARY.md` |
| 8 | Уровни: `FMT-012` поднимается до `MUST`; каноны — два `SHOULD`-правила `FMT-014` (комментарии) и `FMT-015` (`on` + CTE) |
| 9 | Нумерация: `FMT-011` удаляется, ID `FMT-012`/`FMT-013` не перенумеровываются, «дырка» на 011 остаётся |

## Implementation Decisions

- **Итоговый набор правил аспекта Форматирование:** `FMT-001`–`FMT-010` (без изменений по смыслу, кроме `FMT-004`/`FMT-008`), `FMT-011` — **удалено**, `FMT-012` (`MUST`), `FMT-013` (без изменений), `FMT-014` (`SHOULD`, новое), `FMT-015` (`SHOULD`, новое).
- **`FMT-004`**: термин берётся из глоссария; короткий многострочный запрос — «Хорошо»; однострочный — «Плохо». Уровень и маппинг (`LT14`) не меняются.
- **`FMT-008`**: добавляется оговорка «`distinct` остаётся на строке с `select`». Уровень и маппинг (`LT09`) не меняются.
- **`FMT-009`** остаётся `MUST` про отступ вложенных блоков (`LT02`); канон CTE/`on` выносится в `FMT-015`.
- **`FMT-012`** → `MUST`; покрывает смысл («почему», не «что») и типы комментариев (запрет `/* */` в репозитории). «Проверяется линтером: нет».
- **`FMT-014`** (`SHOULD`, линтером не проверяется): однострочный комментарий — на отдельной строке над кодом; исключение — служебные директивы (`-- noqa`, `-- sqlfluff:`).
- **`FMT-015`** (`SHOULD`, линтером не проверяется): `on` на своей строке с отступом 4; канон CTE из решения 5. Конфиг дополняется секцией `[sqlfluff:layout:type:common_table_expression] spacing_within = single` (в **оба** профиля), чтобы канонический вид CTE проходил линтер.
- **`LT08`** (`layout.cte_newline`) намеренно **не** включается: он потребовал бы пустую строку после каждого `)`, что противоречит решению 5. Это фиксируется в обосновании `FMT-015`.
- **Версия** `0.2.0`; класс изменения — MAJOR (удаление правила + запрет, делающий ранее валидный код невалидным), помечается в ADR-0006 и §9.3.
- **§8.2** приводится в соответствие: строка `FMT-011` убирается, `FMT-012` → `MUST`, добавляются `FMT-014`/`FMT-015` (`SHOULD`/нет).

## Testing Decisions

- Единый шов прежний: референсный конфиг SQLFluff + корпус `examples/`, проверка — `python3 scripts/check.py --all`.
- Новые `FMT-014`/`FMT-015` — «проверяется линтером: нет» → фикстур **нет** (инвариант `check_consistency.py`).
- Правка конфига под CTE проверена: корпус остаётся зелёным (40 фикстур).
- Good-фикстуры `examples/fmt-009-good.sql` и `examples/syn-002-good.sql` переводятся на канонический вид CTE; bad-фикстуры не меняются.
- Все блоки «Хорошо» в `STANDARD.md` остаются линтер-чистыми (проверяется вручную/ревью, как и раньше).

## Out of Scope

- Новые правила Нейминга и Синтаксиса.
- Бэклог синтаксиса (`USING`, `CAST` vs `::`, `NULLS FIRST/LAST`, `LIMIT/OFFSET` vs `FETCH`, `NOT IN` vs `NOT EXISTS`).
- Кастомный плагин SQLFluff или внешние проверки для правил «линтером не проверяется».
- Массовое переформатирование существующего кода под новые правила.
