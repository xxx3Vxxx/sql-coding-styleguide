# 03: Запрет блочных комментариев — `FMT-012` до `MUST`

**What to build:** поднять `FMT-012` до `MUST` и включить в него запрет блочных комментариев `/* ... */` в SQL, попадающем в репозиторий. Само правило линтером не проверяется (`нет`) — проверка на ревью. ADR-0006 уже создан.

**Blocked by:** —

**Status:** done

- [x] `FMT-012`: уровень `SHOULD` → `MUST`
- [x] `FMT-012`: правило покрывает смысл («почему», а не «что») и типы комментариев — только `--`; блочные `/* */` в репозиторий не добавляются
- [x] `FMT-012`: оговорено, что локальное/временное использование `/* */` (быстрое отключение кода) допустимо
- [x] Обоснование опирается на единообразие и границу «репозиторий vs локальный черновик»; ложный тезис о неминуемой ошибке вложенности не приводится (PostgreSQL вкладывает блочные комментарии)
- [x] Ссылка на `docs/adr/0006-no-block-comments.md`
- [x] Поле «Проверяется линтером» остаётся `нет`; фикстур нет
- [x] `python3 scripts/check.py --all` — зелёный

## Decisions

- Запрет — `MUST`, хотя ядро SQLFluff блочные комментарии не проверяет: в проекте есть `MUST`-правила без машинной проверки (`NAM-004`–`NAM-009`), а запрет необратим для уже существующего кода → отдельный ADR.
- `FMT-012` владеет и смыслом, и типами комментариев; расположение выносится в `FMT-014` (тикет 04).
