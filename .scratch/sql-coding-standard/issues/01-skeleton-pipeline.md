# 01: Сквозной каркас и конвейер проверки

**What to build:** самый тонкий сквозной путь через весь проект — от документа до машинной проверки. Стандарт со всеми разделами-заголовками, ровно одно правило (`SYN-003`), минимальный конфиг линтера, пара примеров и скрипт, который прогоняет линтер по корпусу примеров и проверяет ожидаемый результат. Это доказывает, что шов «документ → конфиг → примеры → проверка» работает.

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] В стандарте присутствуют все разделы оглавления (§1–§9) с черновыми заголовками
- [ ] Правило `SYN-003` (`<>` вместо `!=`) описано по формату: ID, уровень нормативности, пример «плохо/хорошо», обоснование, поле «проверяется линтером: да»
- [ ] Конфиг линтера включает ровно то, что нужно для `SYN-003`
- [ ] В корпусе примеров есть пара «плохо/хорошо» для `SYN-003`
- [ ] Скрипт проверки прогоняет линтер по корпусу и падает, если ожидаемый результат не совпал
- [ ] Прогон скрипта — зелёный
